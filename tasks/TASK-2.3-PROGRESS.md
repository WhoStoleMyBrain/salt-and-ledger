## Shared implementation contracts

1. One authoritative regional owner. New immutable `CargoItineraryPolicy` (Id, Version=1, Stops), `CargoItineraryStop` (PortId, Commands), `CargoItineraryCommand` (Kind, GoodId, MaximumQuantity, MinimumQuantity, ShortagePolicy, MarginalPriceLimit, CashReserve, MaximumExpenditure, WarehouseReserve). Enum commands: BuyFromMarket, SellToMarket, LoadFromCompanyTownStock, UnloadToCompanyTownStock. Shortage enum: Skip, Wait. Policy bounds 2–4 unique ports, 1–8 commands/stop, at most24 total. Resolve actual routes, goods, company stock ownership; private endpoints are the selected town pool, never guessed foreign facilities.
2. Quantities use existing physical subunits, positive whole 10,000-unit multiples for maximum/minimum (default minimum10000); UI enters whole units and converts once. Reserves use existing physical/money units. MarginalPriceLimit0 means unrestricted; purchase cash reserve and per-command expenditure cap constrain actual exact totals. WarehouseReserve applies only to Load. Reject irrelevant nondefault constraints. No float economic calculations.
3. A command executes the largest eligible quantity between minimum and maximum ONCE per visit, then advances even when below maximum. This is a per-visit order cap, not a hold target. If below minimum, Skip advances with no goods/cash movement; Wait retains the exact cursor and spends no cash. Earlier commands never repeat. Leftover and mixed cargo remain aboard. All transactions use ordinary shared preview/execution/FIFO paths.
4. `RegionalShipSnapshot.Itinerary` and `.ItineraryProgress` are null/omitted for old routes. Immutable `CargoItineraryProgress`: StopIndex, ActionIndex (Count means ready to depart), Cycle (zero-based; advances when departing the final listed stop toward first), LastDecision (kind), LastReason (typed code), LastQuantity, OperationsDay, OperationsUsed. Enabled flag remains the existing authoritative ship flag. During travel StopIndex names the destination and ActionIndex=0. A cycle label is a policy-list pass, not a claim that an initially partial pass completed all stops.
5. At most8 itinerary operations per ship per economic day, including intentional skips and departure; saved OperationsDay/Used prevents repeated dockside clicks bypassing the cap. Wait stops the chain; the eighth command can leave departure for the next day. Daily order stays actor priority/ordinal ID, then all existing phases. Each action reevaluates staged current stock/cash. Old route limit stays4. No same-day arrival/teleport or repeated action after a wait.
6. Apply/replacement is passive and preserves cargo. Requires manual control (automation disabled), actual dock at a new policy stop, and no partial old itinerary visit (ActionIndex must be0 or its command count). Same policy content preserves progress. Configure legacy route from an itinerary obeys the same safe transition. Draft/view always permitted without empty hold; disabling retains position, progress and cargo. Outside-route manual travel yields explicit location blockage; save restoration must distinguish legal paused manual relocation from inconsistent enabled voyage state.
7. RunIdentity gains optional final `itineraryVersion=0` for old identities. New host v3 pooled setup explicitly uses1; only1 with v3/pooled is legal. Comparison group adds `/itinerary-v1`; assignment does not alter identity/seed. New version1 identities use save schema4 even before a route is assigned. Existing schema1/2/3 retain exact fields/fingerprints/bytes. Old pooled runs remain version0 and keep their existing controls; Retry/Load preserve identity, fresh Change Setup/Reroll use1.
8. Core public entry points: `RegionalWorldState.ConfigureItinerary(string shipId, CargoItineraryPolicy policy, bool enabled=false, RegionalWorldSnapshot? expectedSnapshot=null)`; `CargoItineraryEvaluator.ValidatePolicy(snapshot,shipId,policy)`; `.Evaluate(snapshot,shipId)` for applied current work; `.PreviewCommand(snapshot,shipId,policy,stopIndex,actionIndex)` for passive draft/current-quote hypothetical inspection, never remote permission. `RegionalDecision.ItineraryDetail` adapts new typed decisions. Existing RunAutomation/ExecuteAutomation integration stages ordinary operations. UI uses session wrappers and these authoritative views.
9. `CargoItineraryDecision`: Before, ShipId, Kind (Execute, Skip, Wait, Depart, ContinueSailing, Paused), BlockReason, Reason, StopIndex, ActionIndex, command reference, SelectedQuantity, Trade/Transfer/Departure and Preview. `CargoItineraryPresets.BreadLoop(snapshot,shipId)` resolves A=recovery (Bakery), B=food source, C=processing; offers only a draft. Root supplies it; UI must explain missing Bakery capability/store rather than constructing anything. No source stock, funds or hidden grants created by preset.
10. Strict persistence validates bounded policy/progress, version/ownership, unique stops/valid routes/goods, required actual stockpiles, cursor/budget/enums, mutually exclusive policies, voyage/dock consistency and terminal state. Optional fields omit for legacy. Entire continuation including FIFO/cash/progress compares exactly without replaying commands. Diagnostic report includes itinerary and progress via authoritative ship snapshot.
