# Unity 6 integration and verification

The project at `unity/` uses **Unity 6000.6.6f1**. ArchipelagoLab presents complete runs around the four-port region through UI Toolkit; TradingLab preserves the two-port comparison, and Bootstrap runs the original production smoke. Simulation source remains only in `src/SaltAndLedger.Simulation`; the hosts use the same prepared DLL, canonical JSON and generated encyclopedia without duplicating economic operations.

## Prepare a checkout

Install the Editor version in `unity/ProjectSettings/ProjectVersion.txt`, the .NET 10 SDK, and the Python dependencies. From the repository root:

```powershell
python -m pip install -r requirements.txt
dotnet restore SaltAndLedger.sln --locked-mode
python tools/generate_docs.py
python tools/prepare_unity.py
python tools/prepare_unity.py --check
```

Preparation validates the canonical data and rebuilds the existing `netstandard2.1` library in Release using locked dependencies, even if a previous DLL exists. It stages:

| Generated asset | Source |
| --- | --- |
| `unity/Assets/Generated/Simulation/SaltAndLedger.Simulation.dll` | Release build of the existing simulation project |
| `unity/Assets/Generated/Resources/CanonicalContent.json` | Exact bytes of `data/content.json` |
| `unity/Assets/Generated/Resources/Encyclopedia.json` | Current format-version-2 `generated/encyclopedia.json` |
| Asset/folder `.meta` files | Stable GUIDs generated by the preparation tool |
| `unity/.simulation-staging.json` | Source, build configuration, and output hashes |

These files are ignored build outputs. Rerun preparation after editing the simulation, canonical data, shared player help, schemas, generator or relevant build configuration. Missing or stale generated reference data fails explicitly before building; regenerate it first. The read-only `--check` detects changed inputs, missing/modified outputs, and unexpected files in the generated directory; it requires no SDK or `bin/` directory. It does not import or run Unity. Use `--dotnet PATH` if the .NET executable is not on PATH.

Open `unity/` through Unity Hub and allow package resolution/import to finish. Use the project's **.NET Standard 2.1** API compatibility level under Player settings. Unity documents this profile for [managed plug-in compatibility](https://docs.unity3d.com/6000.0/Documentation/Manual/dotnet-profile-support.html). The existing template assets and packages are retained; their presence does not add simulation functionality.

## Newtonsoft ownership

The portable build uses NuGet **Newtonsoft.Json 13.0.3**. Unity's manifest directly pins **`com.unity.nuget.newtonsoft-json` 3.2.2**, and its UPM lock file is committed. Unity supplies the only Newtonsoft assembly used by the Unity host. Do not copy the NuGet Newtonsoft DLL, the .NET 10 demo/test assemblies, or simulation source into `Assets`.

Unity's [package manual](https://docs.unity3d.com/Packages/com.unity.nuget.newtonsoft-json@3.2/manual/index.html) identifies upstream version 13.0.2. Inspection of the installed 3.2.2 package confirmed file version 13.0.2 and assembly identity `Newtonsoft.Json, Version=13.0.0.0, Culture=neutral, PublicKeyToken=30ad4fe6b2a6aeed`, matching the NuGet 13.0.3 assembly identity. This resolves the assembly reference; behavioral compatibility is established only for the configurations exercised below. The package version and upstream library version are different numbering schemes.

### Official Unity Agent Plugin workflow

Tasks 1.2 through 1.5 use the installed `unity@unity-agent-plugin` **`unity:unity-cli`** skill and supported `unity test`/`unity build` commands. The playable hosts also use **`unity:ui`** and **`unity:ui-uitk`**. Batch tests/builds do not require a running Editor or live Pipeline connection; actual scene inspection and screenshots use the supported Pipeline. The primary economic verification remains headless; Unity checks exercise the staged assembly and scene host. No additional dependency DLL is staged. Bootstrap retains its original production outcomes with the expanded canonical catalog.

With the plugin's Unity CLI installed, check its version and discover existing Editors before starting a batch run. If sandbox restrictions prevent network or process discovery, retry with the required access; do not interpret restricted discovery as proof that no Editor is open. These examples assume `unity` is on PATH (the local Windows installation used `%LOCALAPPDATA%/Unity/bin/unity.exe`):

```powershell
unity self-update --check --format json
unity status --project-path "$PWD/unity" --format json
unity editors --installed --format json

$unityProject = (Resolve-Path 'unity').Path
$resultsDir = Join-Path $PWD '.cache/unity-results'
New-Item -ItemType Directory -Force -Path $resultsDir | Out-Null
unity test $unityProject --editor-version 6000.6.6f1 --mode EditMode `
    --filter SaltAndLedger.UnityHost.Tests `
    --output "$resultsDir/editmode.xml" --timeout 600 --format json `
    -- -nographics -logFile "$resultsDir/editmode.log"
if ($LASTEXITCODE -ne 0) { throw "Unity Edit Mode failed: $LASTEXITCODE" }
unity test $unityProject --editor-version 6000.6.6f1 --mode PlayMode `
    --filter SaltAndLedger.UnityHost.Tests `
    --output "$resultsDir/playmode.xml" --timeout 600 --format json `
    -- -nographics -logFile "$resultsDir/playmode.log"
if ($LASTEXITCODE -ne 0) { throw "Unity Play Mode failed: $LASTEXITCODE" }

[xml]$editResults = Get-Content "$resultsDir/editmode.xml"
[xml]$playResults = Get-Content "$resultsDir/playmode.xml"
if ($editResults.'test-run'.result -ne 'Passed' -or [int]$editResults.'test-run'.passed -lt 1 -or
    $playResults.'test-run'.result -ne 'Passed' -or [int]$playResults.'test-run'.passed -lt 1) {
    throw 'Unexpected Unity test outcome or test count; inspect XML and logs.'
}
```

The CLI supplies `-batchmode`, test flags, and result paths. Do not forward reserved flags or add `-quit` to a test run. Inspect individual cases and compare counts with the current verification record; a nonzero result alone does not show that all three scenes ran. Keep logs local; Editor logs may include authentication arguments, so redact them before sharing.

### Direct Editor alternative

For developers without the CLI, the existing direct Editor commands remain usable:

```powershell
$unityEditor = 'E:\UnityInstalls\6000.6.6f1\Editor\Unity.exe'
$unityProject = (Resolve-Path 'unity').Path
$resultsDir = Join-Path $PWD '.cache/unity-results'
New-Item -ItemType Directory -Force -Path $resultsDir | Out-Null

& $unityEditor -batchmode -nographics -projectPath $unityProject `
    -runTests -testPlatform EditMode -assemblyNames SaltAndLedger.UnityHost.EditModeTests `
    -testResults "$resultsDir/editmode.xml" -logFile "$resultsDir/editmode.log" | Out-Host
if ($LASTEXITCODE -ne 0) { throw "Unity Edit Mode failed: $LASTEXITCODE" }

& $unityEditor -batchmode -nographics -projectPath $unityProject `
    -runTests -testPlatform PlayMode -assemblyNames SaltAndLedger.UnityHost.PlayModeTests `
    -testResults "$resultsDir/playmode.xml" -logFile "$resultsDir/playmode.log" | Out-Host
if ($LASTEXITCODE -ne 0) { throw "Unity Play Mode failed: $LASTEXITCODE" }
```

Do **not** add `-quit` to `-runTests`: the test runner owns completion and Editor exit. Inspect the NUnit XML files for a passed result and the expected nonzero test count, as well as the Editor logs; an exit code alone is insufficient evidence. See Unity's [Test Framework command-line reference](https://docs.unity3d.com/6000.2/Documentation/Manual/test-framework/reference-command-line.html).
